OpenTuner M0CKE — User Manual

Version 1.3.2 · Windows DATV receiving and monitoring · November 2026

OpenTuner builds on the original Open Tuner project by ZR6TG. Capabilities vary with the connected hardware and its firmware.

1. Getting started

  1. Install a Windows test build or published release from the OpenTuner M0CKE GitHub repository.
  2. Connect a supported receiver to the PC by USB or Ethernet. For Ethernet devices, confirm the PC and receiver can communicate across the network.
  3. Open Source Settings; select the correct receiver interface and its network addresses and ports as applicable.
  4. Choose the media source, then use CONNECT once the hardware is available.
  5. Enter the receiving frequency, LO offset if required, symbol rate and RF input; press TUNE.

Where an installer includes this manual, the top-bar HELP button opens the local HTML copy in your default browser without requiring an internet connection.

The application supports single-, dual- and four-receiver views when the source supplies those channels. Four-receiver mode uses a 2×2 grid.

3. Connection management

WAITING means no usable hardware has been detected; CONNECT means a receiver is available; CONNECTED means the source has been started. A failed or interrupted link may display an offline or recovery state. A device can be connected while a particular receiver still shows NO LOCK.

For recovery, verify power, IP address, UDP base port and firewall first. The Connect control has a contextual Force connect (skip availability check) action for cases where ICMP/probing does not represent actual receiver availability. Use it only when the device is known to be reachable.

4. Receive tuning and layout

Each receiver has its own FREQ, LO, SR, RF Input and TUNE controls. Frequency is displayed in MHz and symbol rate in kS/s. For example, a 10,491.500 MHz input with a 9,750 MHz LO corresponds to a 741.500 MHz intermediate frequency when the LO offset is enabled.

In four-receiver mode the cards are labelled RX A (top-left), RX B (top-right), RX C (bottom-left) and RX D (bottom-right). A green LOCKED label indicates a demodulator lock; the service name appears in the receiver header.

5. Two PicoTuner Ethernet devices — four receivers

In Source Settings → PicoTuner Ethernet, set PicoTuner 1's IP and base port. Tick Enable second PicoTuner (four receivers) and enter PicoTuner 2's own IP and base port. Both IPs must be different and the port ranges must not overlap. Save settings and reconnect.

Example installation: unit 1 at 192.168.1.91 using base port 9900, unit 2 at 192.168.1.152 using base port 9800. These are examples, not factory defaults. Confirm both device broadcasts report the expected addresses and base ports. The status and video streams must reach the PC.

Four video feeds have been demonstrated with this arrangement. Verify independent tuning and all physical LNB outputs on your own hardware; boards may provide different LNB supply arrangements.

6. LNB power, RF input and LO

Where supported, the top toolbar provides LNB A / LNB B dropdowns with OFF, 13V V and 18V H. In dual-PicoTuner mode, there are separate selectors for device 1 and device 2. They are saved independently and reapplied on reconnection.

RF A/B in each receiver card chooses the tuner RF input; it is separate from selecting an LNB voltage. Not every PicoTuner board has two physical powered outputs: a broadcast may report LNB Y as absent. Do not assume that a menu option implies the hardware output exists.

Enable the LO offset only when necessary for your receive system. Check the LO figure before tuning.

7. Current, TS Info and Tuner Data

Current

Shows receive frequency, modulation error ratio (MER) and decode margin, with visual bars. A Constellation option is shown where the chosen source provides real constellation samples. WinterHill Ethernet status does not supply these constellation coordinates.

TS Info

Shows transport-stream bitrate history and, as available, null packet percentage, received stream status, video/audio codecs, resolution and audio details.

Tuner Data

Can include DVB-S/DVB-S2 state, modulation/MODCOD, RF input, frequency, NIM frequency, LO, symbol rate, service/provider and available error metrics. RF level, BER, carrier offset and LDPC errors are source-dependent. In particular, USB MiniTiouner and Ethernet WinterHill do not necessarily expose identical diagnostics. A dash means the value is not available, not that it is zero.

8. QO-100 BATC Wideband Quick Tune

Enable the QO-100 spectrum checkbox for the BATC wideband display. Click a visible signal to tune a receiver. The spectrum can display RX markers.

RX1 Auto Scan and RX2 Auto Scan use automatic candidate selection. Rotate 30s enables optional receiver rotation between signals. Verify the resulting frequency and symbol rate, particularly for narrow signals or when operating in a four-receiver system. Spectrum-derived information is not equivalent to a local RF spectrum measurement.

9. Receiver video and audio controls

Each receiver provides a volume slider and speaker symbol, MUTE, RECORD, SNAPSHOT and fullscreen controls. Recording and snapshot availability can depend on the media player and active transport stream. Use RECORDINGS and SNAPSHOTS in the top toolbar to access saved content and the relevant media features.

Each receiver's controls operate independently where supported; muting one stream should not intentionally mute all receivers.

10. Presets and BATC Chat

Use PRESETS to manage saved tuning entries, and select a preset to retune. The receiver interface includes BATC CHAT integration for DATV community communication; chat capabilities and access depend on the service configuration and availability.

11. Source Settings and Media Settings

SOURCE SETTINGS opens settings for the selected receiver source. The WinterHill settings dialog adapts to the chosen interface:

  • PicoTuner Ethernet: device 1 IP/base port and optional device 2 IP/base port, plus the PicoTuner Broadcast Listener.
  • WinterHill UDP: UDP network settings for the four-receiver WinterHill system.
  • WinterHill WebSocket: WebSocket IP, WS port and corresponding UDP base port.
  • Always Ask: keeps the interface choice available on connection.

MEDIA SETTINGS opens the application's broader media-related settings and is distinct from receiver network settings.

12. PicoTuner Broadcast Listener

Open PicoTuner (WH) Broadcast Listener from PicoTuner Ethernet Source Settings. The broadcast stream uses UDP 9997 and reports IP address, serial, firmware, UDP base port, receiver state and TS destinations when provided by firmware.

Use the device selector to pick a PicoTuner by IP address. The displayed address and base port relate to the selected unit, not merely whichever unit broadcast most recently. Commands Reset, Reboot, Bootsel and Change Base Port target that unit.

Base-port changes require confirmation. The app checks port format and overlap with other discovered/configured units. Check your PicoTuner firmware documentation for persistence: some base-port changes are forgotten after power is removed. If you change a hardware base port, update the matching Source Settings value before reconnecting.

13. Automatic update checking

OpenTuner checks GitHub for newer published releases at startup. When a newer semantic version is found, the user can open the GitHub releases page. A test build may be newer than the latest published release without triggering an update notification. Update checks require internet access.

Official releases: github.com/makidoja/open_tuner/releases. Experimental Windows builds: GitHub Actions.
